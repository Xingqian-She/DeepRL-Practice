# MountainCar PPO + RND 诊断记录

日期：2026-10-30。原训练日志和模型保留在 `../../runs/`。
本报告中的所有训练、评估和测试都在项目现有 Docker 镜像中运行。

## 结论

仅降低 Predictor 学习率未解决失败。更直接的瓶颈是 PPO 的输入表示和训练信号尺度。
保留原残差网络及 RND 网络，加入策略输入的逐维固定缩放，并将训练外在奖励乘以 0.01，
已在多个训练种子和 GPU 对照中得到高成功率。不需要先削弱 Predictor 网络。

这些是有限预算下的实测结果，不是任意种子、任意设备都收敛的保证。
训练过程中仍有成功率回落；最终回报约 -110 至 -140，也没有达到最优控制。

## 独立评估结果

每个模型用评估种子 20000 开始的 100 个初始条件进行评估。
argmax 与采样策略分别评估；奖励仍为原环境每步 -1。
训练过程的定期评估使用种子 10000，下面的 100 回合评估不参与训练。

| 模型 | 训练步数 | argmax 成功率 | 采样成功率 | argmax 平均回报 |
| --- | ---: | ---: | ---: | ---: |
| 用户本轮原 checkpoint，RND LR=4e-5 | 499712（对应现有日志） | 0% | 0% | -200.00 |
| 输入缩放 + 奖励×0.01，残差网络，CPU seed 0 | 204800 | 100% | 100% | -131.14 |
| 同配置，CPU seed 1 | 499712 | 100% | 98% | -115.41 |
| 同配置，CPU seed 2 | 499712 | 100% | 100% | -125.55 |
| 同配置，GPU seed 0 | 51200 | 100% | 100% | -129.73 |

CPU 与 GPU 结果不同是预期现象；不是同一条训练轨迹。
各模型训练预算不同，表格用于确认可学习性，不构成严格的样本效率排名。
原 checkpoint 没有种子/配置快照；其学习率依据本轮代码及用户说明，而非 checkpoint 元数据。

## 拆分对照说明了什么

以下均保留残差网络、Predictor LR=4e-5，训练种子 0：

| 调整 | 训练步数 | argmax / 采样成功率 | 评估规模 |
| --- | ---: | ---: | --- |
| 未缩放的基线 | 51200 | 0% / 0% | 定期评估 20 回合，seed 10000 |
| 只将 INT_COEF 提至 100 | 102400 | 0% / 0% | 定期评估 20 回合，seed 10000 |
| 只将 EXT_COEF 设为 0 | 204800 | 0% / 0% | 定期评估 20 回合，seed 10000 |
| 仅缩放策略输入 | 102400 | 99% / 100% | 独立评估 100 回合，seed 20000 |
| 仅缩放训练外在奖励 | 102400 | 74% / 86% | 独立评估 100 回合，seed 20000 |
| 两项一起调整 | 204800 | 100% / 100% | 独立评估 100 回合，seed 20000 |
| 缩放策略输入、INT_COEF=0、原外在奖励 | 204800 | 100% / 99% | 独立评估 100 回合，seed 20000 |

两项缩放不是同时不可缺少的硬条件。seed 0 下，仅缩放策略输入就足以显著改善结果，
奖励缩放也有帮助。推荐组合做了额外种子验证，但未证明它是最优组合。

关闭内在优势的对照仍训练 RND 和内在 critic，只是不将内在优势用于策略更新；
它不是完全移除 RND 的独立 PPO 实现。因此能说明“该配置不依赖显式内在优势也能成功”，
不能声称所有 RND 计算都没有影响。MLP 对照也没有显示换网络本身就能解决问题。

## 为什么输入缩放重要

MountainCar 的位置范围是 [-1.2, 0.6]，速度范围是 [-0.07, 0.07]；
初始速度为 0。[Gymnasium 环境定义](https://github.com/Farama-Foundation/Gymnasium/blob/main/gymnasium/envs/classic_control/mountain_car.py)

原实现给 RND 使用了运行均值/方差，但 PPO 使用未经逐维缩放的原始输入。
网络中的 RMSNorm 对隐藏特征做归一化，并不分别对原始位置和速度做标准化。

原残差网络还有一个初始化特性：第一层没有 bias，所有残差 alpha 从 0 开始。
对 `[-1.1, 0]`、`[-0.8, 0]`、`[-0.5, 0]`、`[-0.2, 0]`，第一层输出近似是同一方向、
不同长度的向量；后面的 RMSNorm 又几乎消除了长度差异。
Docker 中实测 seed 0 初始化时，四个位置的每个动作 logit 跨位置变化范围仅约
`2.8e-6 ~ 5.1e-6`，外在价值变化范围约 `2.3e-6`。

这不意味着网络永远无法区分它们，但说明初始表示不适合这组输入。
采用固定观测边界做变换：

```text
position' = (position + 0.3) / 0.9
velocity' = velocity / 0.07
```

把位置和速度都映射到约 [-1, 1]，有助于策略同时利用位置与运动方向。
缩放 buffer 随模型一起保存，评估时自动恢复。

## 为什么好奇心 loss 下降不能单独诊断失败

固定种子基线在第 10240 步，乘系数后的优势标准差为：

```text
外在优势 std ≈ 4.459
内在优势 std ≈ 0.01499
比值 ≈ 0.00336
```

原来没有记录这个量，单看 Predictor loss 会遗漏进入 PPO 的两路信号相差多大。
这个比值描述优势尺度，不等于两路策略梯度的贡献比例，也不能单凭它证明因果。

外在奖励乘以 0.01，同时改变外在 critic 目标单位、价值损失尺度及混合优势的相对权重。
它和仅提高 INT_COEF 并不等价。critic 与策略共享主干、还共同受梯度裁剪影响，
因此训练尺度可能影响实际更新。当前对照支持这种调整有帮助，但没有单独隔离各个梯度机制。

成功模型的原始内在奖励后期同样会下降到约 1e-5 量级。
RND 鼓励的是陌生状态，熟悉后奖励下降符合设计；关键是下降期间策略是否已经学会了有用行为。
[原始 RND 实现](https://github.com/openai/random-network-distillation/blob/master/ppo_agent.py)

## 代码与验证

- `train.py`：命令行参数、种子、独立输出目录、配置快照、定期评估。
- `model.py`：可选的固定逐维输入缩放；原残差网络仍为默认结构，MLP 供对照。
- `ppo_rnd.py`：独立 RND 学习率；损失改为整轮 minibatch 平均；记录裁剪前梯度范数。
- `diagnostics.py`：两路优势尺度、位置/速度范围、动作比例、随机数隔离的评估。
- `evaluate_checkpoint.py`：恢复模型与输入缩放，做独立评估并保存 JSON。
- `reporting.py`：增加诊断曲线，RND/优势尺度使用对数形式显示，减少绘图频率。
- `checkpoint.py`：补充可安全加载的模型结构元数据。
- `summarize_experiments.py`：生成 [summary.csv](summary.csv) 和 [comparison.png](comparison.png)。

10 项回归测试通过，包含真实环境终止/截断、两路 GAE、奖励缩放、target 冻结、
predictor 更新、输入缩放恢复、checkpoint 安全加载、独立评估和 RNG 隔离。
GPU eager 跑完 51200 步；GPU torch.compile 跑完 1024 步采样、更新与保存。
长程 CPU 实验关闭 torch.compile、使用一个 PyTorch CPU 线程；未证明编译后的完整长程收敛。
